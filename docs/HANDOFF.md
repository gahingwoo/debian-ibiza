## Update 2026-10-14 (Bluetooth)
- *** BLUETOOTH WORKS *** (WCN3990 on /dev/ttyHS0; bluez controller "Moto G50 (ibiza)", BD addr 39:90:21:74:07:00, HCI 5.0). - ROOT CAUSES of the old "chip answers for a few seconds, then silent" problem, found after reading the Android HAL (LOS/vendor_blobs/bt/android.hardware.bluetooth@1.0-impl-qti.so strings: "vote for UART CLK ON/OFF", "RXD Wakeup", "Flow off->38.4k->send 0x00->max baud->Flow on", IBS 0xFD/0xFC/0xFE): (1) the host UART (qcom,msm-geni-serial-hs, 4a84000.qcom,qup_uart, xfer_mode SE_DMA, DT qcom,wakeup-byte = 0xFD) RUNTIME-SUSPENDS when idle (power/runtime_status "suspended", power/control "auto") and then drops chip data. Fix: `echo on > /sys/devices/platform/soc/4a84000.qcom,qup_uart/power/control`. (2) NEVER close ttyHS0 after the chip is up: closing shuts the UART down (RTS drops), the chip goes to sleep and then ignores everything; kernel btattach on /dev/ttyHS0 directly therefore failed. Fix: one resident perl process keeps the tty open for good and exposes it as a pty; btattach (-P h4) attaches the kernel to that pty. (3) The kernel hci_qca ROME path cannot download the firmware (it sends a 243-byte FIRST TLV segment which kills the chip's TLV header parser); userspace sends the first segment as 16 bytes, then 243-byte segments, each acked, then HCI reset (never the EDL patch-reset 0xfc00/05). (4) The chip is on shared rails with WiFi, so btpower's power-off ioctl is a no-op while WiFi is up: only ONE bring-up per boot works (a second attempt in the same boot gets no answer at all) - reboot before retrying.

## Kernel facts learned this session
- No CONFIG_DEVTMPFS, no FHANDLE, no AUTOFS, no TMPFS_POSIX_ACL. systemd treats the devtmpfs mount of /dev as fatal and freezes (waitid(P_ALL) loop, no output) unless /dev is already a mountpoint: init mounts tmpfs on /mnt/root/dev and mknods everything from /sys/class/*/*/dev (mkdevs, must run BEFORE moving /sys) and then switch_root. No udev hotplug nodes (udevd cannot create nodes); later USB devices will not get /dev entries.
- /dev/kmsg in the initramfs used to be a plain file (echo created it): all earlier LOG lines were lost. Fixed with mknod c 1 11.
- busybox picks the applet from argv[0]: the copy in the rootfs must be named `busybox` (usr/local/sbin/busybox), `ibiza-bb` fails with exit 127 and panics PID 1.
- ACM serial and telnetd failed before only because /dev/ptmx and /dev/ttyGS0 nodes did not exist.
- cpufreq: policy0 (cpu0-5) 300 MHz..1.80 GHz, policy6 (cpu6-7) 768 MHz..2.04 GHz; governors conservative powersave performance schedutil; kernel default is performance, ibiza-cpufreq.service sets schedutil.
- Magisk busybox has no `reboot` applet; use sysrq.
